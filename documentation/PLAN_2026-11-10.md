Verdict: **no Slovak cell is both ≤8% and ≤2 s.** Best accuracy is kinit with pause or clause cutting at about 2.8-3.0 s (p90 4.1-4.3 s). Faster agreement (0.5 s) breaks because the decode takes longer than the step. Czech with agreement every 1.0 s is within 0.3 s of the goal. Recognition alone already uses 2.8 s, so the end-to-end 2 s target for Slovak input needs a streaming-native recogniser (Nemotron streaming reached 0.6 s lag on English on the Mac but scored 28% on Slovak), not a better cutting rule.
Decision needed from the maintainer: (a) accept about 3 s for Slovak input with kinit + clause and say so in the docs; (b) invest in a Slovak-fine-tuned streaming recogniser (large); (c) Czech input now.

## Slovak input under 2 s: measured, not viable on Mac (2026-11-11)
- **Real speech test (Mac, `Me speaking sk from the script.m4a`, SK→EN, `agree_short`):** median 15.4 s, 3 segments in 35 s — SK input broken for this voice.
- **Generic Piper Slovak test (`processed/testaudio/sk_paced.wav`, SK→EN, `agree_short`):** median 3.88–5.59 s (1.0×/1.25×/adaptive), `first_audio_after_source_end` ~3.9 s — the Whisper `large-v3-turbo-sk` CT2 model is too slow on Mac CPU (~0.7 s/call floor, padded to 30 s). Even clean native-like Slovak speech doesn't meet <2 s.
- **Czech fallback works:** `language_eval_cs-en.wav` CS→EN median 1.18 s, p90 2.84 s, 25 segments — under 2 s median.
- **Nemotron 3.5 ASR streaming 0.6B** was already benched 2026-10-01, NEGATIVE for SK (WER 0.75–0.86, language drift). Do not retest without a version change or SK fine-tune.
- **Decision:** Czech is the viable input fallback on Mac. SK input under 2 s requires a GPU (T4) with faster-whisper turbo (0.4–0.5 s per 10 s clip) or a streaming-native recogniser — not available on this Mac.
- **SloPalSpeech fine-tune** remains a research option for later (50–100 h subset, streamed from HF).

**Higgs TTS 3 and Fish Audio S2-Pro are NOT runnable on Kaggle T4.** Both require the SGLang-Omni serving stack, which depends on `sglang`, which requires the `outlines_core` Rust extension. Kaggle T4 runs Python 3.13.16 with no Rust toolchain and no pre-built `outlines_core` wheel, so `sglang` cannot be installed. This is a fundamental Python-version/toolchain incompatibility, not a configuration issue. The kernels were pushed 8 times across both models; every approach (plain transformers, AutoModel, AutoModelForCausalLM, pipeline, SGLang-Omni via pip, SGLang-Omni from source) failed.
