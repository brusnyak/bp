## Product Designer Judgment

### Bounded Implementation Direction

**Scope:** Update homepage, live session, and enrollment as a single linear journey. No visual rebrand. Preserve Playfair Display (headings), Montserrat (body), berry `#C41E3A`, dark navy `#0A1C4F`, plain HTML/CSS/JS.

**Primary CTA:** "Start Speech Translation" (one per page, hero position).

**Journey Phases:**
1. **Prep:** Route status, privacy/storage wording, clone readiness badge.
2. **Sound Check:** Mic test, device selector, engine/language controls.
3. **Start:** Capture begins, route status updates to active.
4. **Captions:** Live subtitles, Picture-in-Picture toggle.
5. **Recover:** Error states (JWT mismatch, virtual input rejected, mic paused).
6. **Safe Stop:** Capture ends, metrics snapshot, data handling confirmation.

**Separation:** Research lab/advanced engines moved to a distinct `/lab` section, visually separated from the main meeting flow.

**Truthfulness:** Persistent route status indicator (qualified/unqualified), no exaggerated production claims, no private voice evidence public.

---

### Roast

The current homepage is a thesis graveyard: walls of text, exaggerated production claims, and a live page that feels like a debug console. You’re asking users to trust a speech translation system with JWT mismatches, resuming stops, and rejected virtual inputs while advertising cloned voices that don’t exist yet. The mic pauses during playback—imagine trying to speak while the system talks over you. Async sink routing is broken, and private voice evidence is somehow public. This isn’t a product; it’s a liability with a berry-colored button. Fix the plumbing before you paint the walls.

---

### Assumptions

- No commercial proof or third-party endorsements exist.
- Generic TTS is the only baseline; cloned voice and EN↔SK plus Czech are future requirements.
- Hardware/route quality is currently unqualified.
- No third-party names, contacts, private audio, or credentials are supplied.
- Plain HTML/CSS/JS only; no build tools or frameworks.

### Layout

**Homepage (`/`)**
- Hero section: Dark navy `#0A1C4F` background, Playfair Display heading in white, Montserrat body in white, berry `#C41E3A` primary CTA button.
- Route status bar: Full-width, light gray background, dark text, persistent across all pages.
- Features grid: 3 columns, Montserrat body, no exaggerated claims.
- Lab link: Text link to `/lab`, visually distinct (gray, smaller).

**Live Session (`/live`)**
- Top: Route status bar (persistent).
- Center: Captions area (large, Montserrat, high contrast), PiP toggle button.
- Right sidebar: Metrics (latency, audio level, route quality), device selector, language/engine controls.
- Bottom: Berry `#C41E3A` "Safe Stop" button, recovery message area (red text if error).

**Enrollment (`/enroll`)**
- Form: Name, email (optional), consent checkbox (local processing only, no audio stored).
- Clone readiness badge: Gray, "Not Ready" until route qualified.
- CTA: Disabled until route status changes to qualified.

**Research Lab (`/lab`)**
- Separate navigation, distinct heading style, warning banner: "Experimental. Not for production."

---

### Acceptance Checks

1. **Visual Tokens:** Playfair Display headings, Montserrat body, berry `#C41E3A` primary CTA, dark navy `#0A1C4F` hero, plain HTML/CSS/JS only.
2. **Single CTA:** One primary CTA per page, hero position, berry color.
3. **Journey Flow:** Prep → Sound Check → Start → Captions → Recover → Safe Stop, linear and unbroken.
4. **Route Status:** Persistent, truthful, displays "Qualified" or "Unqualified" only.
5. **Privacy Wording:** Explicit "Local Processing Only," "No Audio Stored," "No Private Voice Evidence Public."
6. **Clone Readiness:** Badge shows "Not Ready" by default, CTA disabled until qualified.
7. **Recovery States:** All five core failures have visible, actionable messages.
8. **Lab Separation:** `/lab` visually and navigationally separated from main meeting flow.
9. **No Exaggerated Claims:** No production metrics, no "enterprise-grade," no "99% accuracy."
10. **No Third-Party References:** No names, contacts, credentials, or private audio.
