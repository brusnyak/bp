Live Speech Translation

Speak in one language. Hear translated speech and read live captions. Recognition, translation and voice run locally on your own machine — no cloud speech service. Install the models once; the default pipeline then runs offline.

Quick start

Requires Python 3.11 or 3.12, Git, ffmpeg and internet access for installation. Setup downloads dependencies and model weights. Start with generic Piper voices; personal recordings are not included.

  1. Clone the repository.
    git clone https://github.com/brusnyak/bp.git
cd bp
  2. Set up the profile for your machine. This example installs Czech, Slovak and German with English.
    python3.11 scripts/setup.py --profile mac --langs cs,sk,de

    Apple Silicon: mac. NVIDIA CUDA: replace it with nvidia. Other laptops: use cpu. On Windows use your Python 3.11 executable.

  3. Run with the matching profile.
    make run PRESET=mac

    Use PRESET=nvidia or PRESET=cpu for the other profiles. Windows: run .venv\Scripts\python.exe app.py.

  4. Open http://localhost:8000 in Chrome or Edge. Select languages, choose Microphone and Output, use Test microphone, wear headphones and press Start.

Commands: README quick start · Makefile · setup.py.

Lag is measured from a speech fragment's estimated end to the start of translated audio in a simulated sequential player. It includes the playback queue; it is not physical microphone-to-speaker delay. p90 means nine out of ten fragments were at or below that delay. Negative drift means the lag did not grow.

X-Voice's short test is one sentence, roughly 3–5 s of speech; stage 1 actually generated 4.6–6.0 s of audio. Longer sentences take longer. Which should I use?

  • Live default → Piper. Start here for a working audio path.
  • Czech / English clone with streaming → XTTS. Best tested synthesis candidate; non-commercial weights and live-route validation still apply.
  • Slovak clone → X-Voice on a fast GPU. Unproven for live use; it waits for a whole phrase.

Hardware

On a laptop

Piper voice and Whisper recognition run locally. Apple Silicon offers MLX; Nemotron streaming has a measured English-input route on the M1 Pro. Optional engines need their own packages and assets. CPU-only machines have less latency headroom.

With an NVIDIA GPU

Use GPU compute for cloning experiments and low-lag Slovak input. Ampere or newer with 24 GB is recommended for those experiments, not a proven route guarantee. A T4 can test XTTS and X-Voice but failed intelligible Higgs output.

Language and hardware profiles · Measured voice memory. Leave headroom for recognition, translation and voice together; isolated model memory does not prove they fit concurrently.

Use it in a conference room

Feed a meeting or AV mixer

Select a virtual cable in the live page's Output control, then choose that cable as the meeting application's microphone. Use BlackHole on macOS, VB-Cable on Windows, or a PipeWire/PulseAudio virtual sink on Linux. Keep the source microphone isolated from playback.

Let listeners choose a language

Open More → Audience broadcast (room mode) → Start room. Share the audience link or QR code. Listeners open it on their phones, select a language and listen with earbuds. Subtitles can also pop out from the Translation panel.

For phone access, serve HTTPS on a trusted network:

BP_HTTPS=1 BP_HOST=0.0.0.0 make run

Trust the certificate on each device or provide a trusted certificate. Room mode is experimental; test your actual listener count, network and audio path before an event.

Integration guide: routing, API, deployment checklist and troubleshooting

Run your own accuracy test

  1. Read and record the matching language in the multilingual reading script. Use the actual microphone and room; keep the original recording.
  2. Score recognition against that script with installed local models.
    .venv/bin/python scripts/score_reading.py recording.wav en
  3. For a route test, use a prepared, running local backend and replay a recording at real time. These commands are for your own test, after setup.
    .venv/bin/python scripts/live/paced_replay.py recording.wav --base http://localhost:8000 --src en --tgt sk --tts piper --seconds 60 --out processed/replay.json
.venv/bin/python scripts/live/score_success.py processed/replay.json reference.json --rate 1.0

    reference.json must describe that recording: text plus sentences entries with text, start and end in seconds. Generated fixtures come from make_test_audio.py. Replay does not score translation meaning; have a bilingual listener review it.

Read the scores

Word error rate (WER) counts substitutions, missing words and extra words relative to the reference. Lower is better. RTF below 1 means synthesis keeps up with playback. Neither measures translation meaning or whether a clone sounds like its speaker.

Read the latency chart

In More → Diagnostics: latency and activity log, each fragment has a stacked bar: hold → STT → MT → TTS-first → queue. Hold is waiting for enough speech; the chart’s Queue / other part is unattributed server time, not measured browser backlog. The 2 s line is a goal, not a promise. Compare the playback backlog separately: a growing backlog means audio is falling behind.

Methods: score_reading.py, paced_replay.py, score_success.py, benchmarks. First runs may fetch models in scoring tools; provision them before testing offline.

Known limits

  • One speaker at a time; overlapping speakers are not separated.
  • Noise, accents, language and hardware can change recognition quality and delay.
  • Slovak input and cloned voices remain experimental. Successful generation alone does not establish identity or intelligibility.
  • Room mode needs validation with your actual devices, languages and listener count.
  • Fresh-install and output-device behaviour vary across platforms. Chrome or Edge is required for browser output selection.
  • Installation downloads models. Processing stays on the host; shared use needs access, retention and recording policies.
