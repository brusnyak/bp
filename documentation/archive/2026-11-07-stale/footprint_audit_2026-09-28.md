## Torch: proven vs assumed

"We do not use torch" is **not true as the code stands**, but it is *nearly* true:

- **Live path (only 3 sites matter):** `backend/hardware.py` (`_cuda/_rocm/_mps` do a bare
  `import torch` inside each probe → a torch-free install **raises ImportError** at
  `detect_backend`), `backend/mt/ctranslate2_mt.py:3` (top-level import, used once for an
  MPS check although MT is initialized with `device="cpu"`), `backend/main.py:116/1138`
  (top-level import, used for one `isinstance(audio_wav, torch.Tensor)`).
- **Genuinely needs torch:** `backend/tts/coqui_tts.py` (XTTS), `omni_tts.py`,
  `hybrid_tts.py` (OpenVoice), `mt/nllb_mt.py`, `mt/hybrid_mt.py`, plus the training/eval
  scripts (which belong in `.venv-train` anyway).
- **Verdict:** a torch-free **core** profile is reachable with a ~10-line change (guard the
  3 live-path sites). It must not be a global removal: XTTS and Hybrid need torch on
  macOS/Linux, and `make install`'s HF→CT2 conversion needs transformers + torch.

## Ranked cut list

| # | Cut | Saves | Cost / risk | Needs a decision? |
|---|---|---|---|---|
| 1 | Split requirements: `core` (Piper+whisper+Opus-MT+API+tests) vs `extras` (xtts, omnivoice, hybrid, eval, plotting, playwright) | **~1.5 GB venv + 1.6 GB browsers** | guard 3 torch imports; core profile loses XTTS/Hybrid by design | yes — is XTTS still in the thesis narrative? |
| 2 | Drop `ct2_models/` from git (`make install` already converts them) | **225 MB per clone** | install now needs torch+transformers+network (it already does) | no |
| 3 | Drop `Helsinki-NLP--opus-mt-en-cs` (CZ target) | 75 MB | CZ leaves the product; the jirka fallback clip is the only CZ artifact kept | yes — CZ in scope? |
| 4 | Piper voices: keep only one of `en_US-personal-medium` / `en_US-personal-v2` | 60 MB | both are registered engines (`piper_personal` vs `piper_personal_v2`) | yes — which EN voice ships? |
| 5 | Delete root junk + `onnx_models/` + dead `test_*.py` / `benchmark_*.py` / `transcribe.py` | ~1 MB, big readability win | verify each has no importer first | no |
| 6 | `bootstrap_cz/`, `bootstrap_de/` out of git | 6.4 MB | re-recordable; DE was blocked anyway | yes — archive where? |
| 7 | `git gc` on the Mac checkout | 305 MB **locally** | none | no |
| 8 | `test/ui_*_tests.py` + playwright → optional, skip when absent | 1.6 GB browsers | they are not pytest-collected today (`*_tests.py` ≠ `*_test.py`) | no |

**The honest limit:** items 2–8 shrink the checkout and future growth, but **clone size
stays ~450 MB (pack) unless history is rewritten** with `git-filter-repo` — old blobs live
in the pack forever. For a thesis repo with an audit trail, keep history and use what
`SETUP_WINDOWS.md` already documents: `git clone --filter=blob:none --no-checkout` +
sparse-checkout excluding `ct2_models/`, `*.onnx`, `speaker_voices/`, `bootstrap_*`.
Rewriting history is a separate, explicit decision — not taken here.

## What "setup takes too long" actually is

Wall time is dominated by downloads, not by dependency resolution: torch (~200–800 MB by
platform), the whisper size in use (base 145 MB / small 480 MB / turbo 1.5 GB), XTTS ~2 GB,
the OpenVoice converter ~200 MB, 3 Piper bases 190 MB, plus the 3 CT2 conversions. A core
profile removes the XTTS/OpenVoice/Coqui share entirely and skips the heaviest
dictionaries; that is the gap between "half an hour" and "a few minutes" on a fresh
machine, measured as 2.2 GB → ~0.7 GB of venv.

## Sequencing (why the diet waits)

The Windows laptop is editing exactly the files a diet touches (`requirements*`,
`setup_windows.ps1`, install docs) while it fixes SK→EN translation. A diet on the Mac now
guarantees conflicts on the highest-churn files. Order:

1. Windows lands its branch (setup slim-down + SK→EN quality) → Mac pulls, then runs
   `make test` + `test/interrupt_smoke_test.py` + `make demo-check`.
2. Execute cuts 1–8 in one commit per category, on top of both machines' knowledge.
3. Re-run the same three checks + the Linux pass (`documentation/linux_setup_and_test.md`).
4. Only then push and demo.

Cuts 5 and 7 do not overlap the Windows diff and can be done before the pull.
